## 2. Executive assessment

V2 is scientifically transparent and unusually well evidenced. The public package is clean; the external bundle and raw cache reconcile exactly to their manifests; the signed reference is internally consistent; both retained outputs pass artifact and numeric-claim reconciliation; the isolated reproduce output is supported by an offline two-run determinism receipt; the full output is supported by raw-cache, Python–R, and reference-comparison evidence; all 53 registered manuscript artifacts are present; all 92 registered numeric claims pass; and V1 remains byte-for-byte consistent with its frozen baseline contract.

The final serialization incident is also adequately closed. It was a single JSON key-order mismatch, not a scientific-value mismatch. The producer was corrected, a regression test was added, the reference was not modified, the completed analytical output was normalized, and the final validation/finalization stage returned exit code 0. The relevant artifact now has the same SHA-256 hash in the signed reference, full output, and isolated output.

However, the public runner does not reject output directories that overlap the user-supplied external `--data-dir` or `--raw-dir`. A destination nested inside either frozen input root currently passes the runner's initial output-path validator. Because the runner prepares the output and creates temporary execution roots under the output parent, and because component staging copies external input trees, this can mutate a frozen input area and can trigger recursive copying or uncontrolled disk growth. This is a release-safety defect in the public entry point.

Accordingly, the package is **not releasable in its current code state**, despite the analytical artifacts themselves being strongly validated.

## 3. Release-blocking finding

### M1 — External input/output path overlap is not rejected

**Severity:** Major / release blocker  
**Affected entry point:** `PUBLIC/run_replication.py`  
**Disposition:** Must be fixed and regression-tested before release

#### Evidence

`run_replication.py:1397-1412` validates the requested output only against package-local protected locations: the package root, public code, public data, and the reference tree. The function is not given the resolved user-supplied `data_dir` or `raw_dir`.

The main entry point resolves all three paths at `run_replication.py:1551-1553`, but calls the output validator without the resolved external input roots. It then performs preflight and output preparation at `run_replication.py:1564-1577`.

For the CAGED/full path, the runner creates a temporary runtime under `output_dir.parent` and materializes execution inputs at `run_replication.py:1581-1604`. `materialize_execution_root` copies the data tree at `run_replication.py:1136-1153`. The component runner independently stages the external data tree at `code/component_pipeline.py:193-195` and creates its output and temporary runtime under the requested output parent at `code/component_pipeline.py:587-600`.

The public documentation promises a stronger invariant: `README.md:84-87` states that code, inputs, and the signed reference are never valid output destinations.

The current validator was exercised read-only with nonexistent descendants of the actual frozen external roots. Both were accepted:

```text
/Users/manebrasil/Documents/Projects/Dissetação Mestrado/Replication Package/_bundle/v2/audit-output-that-does-not-exist
exists=False accepted=True

/Users/manebrasil/Documents/Projects/Dissetação Mestrado/Replication Package/_raw/v2/audit-output-that-does-not-exist
exists=False accepted=True
```

No directory or file was created by this probe.

#### Why this blocks release

An output nested in `BUNDLE` or `RAW` pollutes a frozen input tree and invalidates its manifest contract. More severely, runtime staging can place a temporary directory inside the source tree that is then being copied. Depending on traversal order and target, this can copy an output or temporary runtime into itself, recurse, fail with path explosion, or consume large amounts of disk before failing.

Some equal-to or ancestor cases may be refused later as a side effect of the nonempty-output guard. That is not an adequate safety contract: all bidirectional overlap must be rejected explicitly, after canonical path resolution and before preflight, directory creation, cleanup, temporary runtime creation, or input staging.

#### Required implementation invariant

Pass the resolved `data_dir` and `raw_dir` into the output-safety validator. After resolving symlinks and normalizing paths, reject each input root when any of the following is true:

```text
output == input
output is a descendant of input
input is a descendant of output
```

In Python terms, the safety decision should cover equality and both directions of `Path.is_relative_to(...)` after `Path.resolve(...)`. The validation must run before any filesystem mutation.

#### Required regression tests

Use distinct fixture parents for the data and raw roots so each case proves the intended relationship independently. At minimum, add all six explicit negative tests:

1. `output_dir == data_dir`
2. `output_dir` nested inside `data_dir`
3. `output_dir` is an ancestor of `data_dir`
4. `output_dir == raw_dir`
5. `output_dir` nested inside `raw_dir`
6. `output_dir` is an ancestor of `raw_dir`

Also add:

- a symlink-alias test proving that textual path differences cannot bypass overlap detection;
- a positive test proving that a disjoint sibling output remains accepted; and
- an entry-point integration test proving rejection occurs before preflight, output preparation, deletion/overwrite handling, temporary runtime creation, and staging.

The tests should assert both the expected exception/message and that no candidate output, marker, or temporary directory was created.

## 4. Nonblocking findings and advisories

### m1 — The documented public test command does not fully describe the external-data mount requirement

**Severity:** Minor documentation/test ergonomics issue  
**Disposition:** Clarify before or with the blocker fix

`README.md:141-150` gives the public verification command `uv run pytest -q tests`. In the distributed public tree, `PUBLIC/data` intentionally contains only `.gitignore`; the frozen analytical data live in `BUNDLE`. One release-focused test, `test_rais_offline_bundle_carries_the_frozen_acquisition_gate`, reads a path rooted directly at `PACKAGE_ROOT/data` rather than using the runner's external-data path context.

In the audited public layout, the release-focused subset therefore produced one failure caused solely by the absent mount. Excluding that mount-dependent test, the same subset produced **137 passed, 1 deselected** in 12.02 seconds. The expected file exists in `BUNDLE` and matches the bundle manifest:

```text

SHA-256: 4ec44876e80d12e7ea31450e6578b3ca6261245d8f640fe2f637ef692dd53abd
```

Its substantive gates pass (`R-G1`, `R-G2`) and it correctly declares no treatment coefficient. This is not an analytical failure. The README should state exactly how `BUNDLE` must be mounted or copied for the full test suite, or the test harness should consume an explicit external data-root fixture consistently with the public CLI.

### a1 — “Signed reference” means a checksum-sealed reference, not third-party authentication

**Severity:** Advisory  
**Disposition:** Terminology should remain precise

The reference signature is a canonical, unkeyed SHA-256 digest. It provides strong internal tamper evidence, and that integrity check passes. It is not a digital signature tied to an external identity or key. Authenticity therefore depends on the release channel and external anchoring of the published digest. This is not a package inconsistency, but readers should not infer cryptographic authorship authentication from the word “signed.”

### a2 — Only one isolated output tree is retained

**Severity:** Evidentiary advisory  
**Disposition:** Acceptable with the retained provenance receipt

The isolated determinism receipt records two network-denied runs with zero differences, but only `reproduce-1` remains available for independent inspection. The retained tree independently reproduces the receipt's tree hash exactly. This is adequate as release evidence, though retaining both trees or a separately signed second-tree manifest would strengthen future forensic auditability.

## 11. Scientific limitations are disclosed, not hidden

The following are substantive limitations of the empirical evidence, but they are not software defects because the package reports them explicitly and withholds causal authorization:

- CAGED's master pretrend support reports 51/51 failures, including three non-positive-semidefinite cases; no specification is designated as passing or recommended.
- CAGED and DDD estimates are labeled exploratory rather than promoted as causally identified effects.
- RAIS fails 2 of 3 pretrend tests and sets causal authorization to false.
- PNADc fails 12 of 12 pretrend tests and sets causal authorization to false.
- The spatial pipeline fails the support gate and stops before real-treatment estimation.
- No failed or non-PSD pretrend is silently converted into approval, and no Family F coefficient or p-value is fabricated.

These limitations are accurately summarized in `README.md:103-118` and `RESEARCH_DESIGN.md:70-106`. A release may transparently include such exploratory estimates; it may not describe them as established causal effects. The audited package respects that boundary.
